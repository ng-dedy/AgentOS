# Milestone 2C: audit and remediation plan

Date: 2026-11-11. Base: `claude/milestone-2b-durable` (PR #2, stacked on PR #1). Neither PR is merged.

Baseline before any change (this environment, Postgres 16, Temporal dev server): typecheck 10/10, lint and boundaries pass, unit and API tests 126 pass, durability 13/13 pass.

## Audit findings, ranked

Severity: **P0** blocks any production deployment, **P1** loses data or money under realistic failure, **P2** operational gap.

| # | Sev | Area | Finding | Evidence |
|---|---|---|---|---|
| 1 | P0 | Key management | The only KMS is `LocalDevKms`. Its KEKs live in an environment variable, and `AGENTOS_DEV_KMS_ALLOW_PRODUCTION=true` lets it run in production. | `packages/platform/src/credentials/kms.ts` |
| 2 | P0 | Key management | With no KMS configured, `createKms` returns `null` and the server starts anyway. Credential storage is then silently off (writes return 503 and runs fail as "not configured"). | `createKms`, `CredentialService.enabled` |
| 3 | P0 | Execution | `AGENTOS_WORKFLOW_ENGINE` defaults to `inprocess`. A production deployment that forgets the variable runs agents inside the API with no durability, and restarts mark runs failed. | `packages/platform/src/config.ts`, `apps/api/src/server.ts` |
| 4 | P0 | Temporal | Only address and namespace are configurable. No TLS, mTLS or API key, so Temporal Cloud or a secured cluster cannot be used. | `packages/workflows/src/client.ts`, `worker.ts` |
| 5 | P0 | Config | No production validation at all. The mock provider, insecure cookies (`SESSION_COOKIE_SECURE` defaults to false) and an http `WEB_ORIGIN` are all accepted in production. "Production" is only inferred from `NODE_ENV`. | `apps/api/src/config.ts` |
| 6 | P1 | Events | Documented race: the listener's catch-up uses `seq > lastSeen`. A transaction that takes seq 10 and commits after seq 11 is skipped if the listener reconnected in between. `Last-Event-ID` replay has the same flaw: a client that saw 11 never gets 10. | 2B report, limitation 4; `pgListener.ts`, `sse.ts` |
| 7 | P1 | Budget | The tree spend limit is checked after the fact, so a run can overshoot by a whole call. Nothing is reserved before a call, so parallel steps could both pass. | `AgentEngine.checkTreeBudget`, `checkRunLimits` |
| 8 | P1 | Budget | If a worker dies after the provider replied but before the turn was stored, the retry calls the provider again. Nothing records that the first call happened, so the possible double charge is invisible. The `attempt` column exists but is never written. | 2B report, limitation 1; `callAndRecord` |
| 9 | P1 | Key management | Every model turn decrypts the key again. With a managed KMS that is one network call per turn, and a KMS outage fails runs with no clear error class. | `CredentialService.resolve` |
| 10 | P2 | Ops | `/health` always returns ok. `/system/health` needs a user session, so an orchestrator has no unauthenticated readiness probe. No Prometheus metrics. | `apps/api/src/app.ts` |
| 11 | P2 | Ops | API shutdown calls `app.close()` straight away: open SSE streams are cut without a drain, readiness is never withdrawn, and there is no forced-exit deadline. The worker has no shutdown deadline either. | `server.ts`, `apps/worker/src/main.ts` |
| 12 | P2 | Temporal | Activity timeouts and retry counts are hard-coded. Workers have no deployment version or build id, so a code change can reach running workflows unannounced. The replay test only replays histories that the current code just produced. | `workflows/agentTask.ts`, `durability.test.ts` |
| 13 | P2 | Temporal | If Temporal is unreachable when the API starts, `Connection.connect` throws and the API exits. No bounded retry, no clear error. | `TemporalWorkflowEngine.connect` |
| 14 | P2 | Docs | No deployment runbook, backup and recovery, incident response or migration procedure. | `docs/` |

Checked and found acceptable: org scoping in routes (`organizationId` from session), owner-only credential and approval routes, log redaction of credential fields, AAD binding of ciphertext to org, provider and row, the package boundary checker.

Noted but out of scope for 2C (risk register): `trustProxy: false` keys rate limits on the load balancer address behind a proxy; no session rotation on privilege change; no CSRF token (SameSite=Lax cookie plus CORS allowlist only).

## Remediation plan

Order follows severity and dependency. Each item lists its verification.

1. **Production config gate** (findings 2, 3, 5). Add `AGENTOS_ENV` (`development` | `test` | `production`, with `NODE_ENV=production` also treated as production). Add one `validateProductionConfig()` used by the API and the worker that collects every violation and refuses to start with a single, clear error. It rejects: an engine other than Temporal, a KMS other than a managed one (including any `AGENTOS_DEV_KMS_*` variable), the mock provider, Temporal without TLS, insecure cookies, a non-https web origin, and a weak metrics token. Tests: one per rule, plus a real-process test that starts the API with an unsafe production env and asserts it exits non-zero with the reason.
2. **AWS KMS adapter** (1, 2, 9). Use `GenerateDataKey` (AES_256) for new data keys and `Decrypt` with `KeyId` pinned to an allowlist. The encryption context is structured (`organizationId`, `provider`, `credentialId`, `purpose`), so IAM policies can condition on `kms:EncryptionContext:organizationId`. Errors are classified (configuration and permission versus throttling and outage) and never include key material. Add an audit row for decrypt failures, which signal tampering or isolation. Add a short-TTL, per-process cache of decrypted keys that is bounded, keyed by row id and `updatedAt`, and cleared on shutdown. Keep `LocalDevKms` (its wraps stay readable: same AAD string). Remove the production override. Add rotation across KMS keys (`AGENTOS_AWS_KMS_PREVIOUS_KEY_IDS` and the existing `credentials:rotate`). Tests: unit tests against a fake KMS client, and integration tests against a real KMS emulator (moto) covering encrypt, decrypt, a context mismatch refused by the KMS, cross-org isolation, rotation and deletion. Real AWS stays unverified.
3. **Temporal production connectivity** (4, 12, 13). Add TLS (server CA, mTLS client cert and key, SNI override) and an API key for both client and worker. Make activity timeouts, retry attempts and workflow run timeouts configurable through `WorkflowOptions`. Those options are recorded in history and default to the 2B values, so old histories replay unchanged. Connect with bounded retries and a clear error. Add worker deployment versioning (`workerDeploymentOptions`, a build id) behind configuration, and an optional prebuilt workflow bundle. Add a worker readiness and liveness server and a shutdown deadline. Tests: config to connection-options mapping, a TLS handshake against a local TLS endpoint, connection refused handling, replay of committed 2B history fixtures against the new code, and a real-process worker SIGTERM drain test.
4. **Event cursor** (6). Store the inserting transaction id (`xid8`, `pg_current_xact_id()`) on each `RunEvent`. The listener reconciles with `txid >= watermark`, where the watermark is the `xmin` of its previous snapshot. Every transaction below that `xmin` had finished when the previous query ran, so nothing committed can be skipped, however late it commits. Duplicates are dropped by seq. SSE ids carry a resume cursor (`<watermark>.<seq>`), and replay from a cursor uses the same rule. Delivery is at-least-once with seq-based dedupe on the server and in the web client. The legacy numeric `Last-Event-ID` still works. Tests: the delayed-commit race reproduced with two real connections (a transaction holding seq N open while N+1 commits), concurrent writers, listener `pg_terminate_backend`, two API instances, and a client reconnect across a late commit.
5. **Budget hardening** (7, 8). Add a `ModelCallAttempt` ledger. Before each provider call, reserve a conservative maximum cost: estimated input tokens times the input price, plus `maxOutputTokens` times the output price. Unpriced models use a configured allowance. The reservation is checked against the run budget and the task-tree budget, together with spend and open reservations, under an advisory lock on the root task. It is settled with the actual usage after the call. A reservation left open by a dead worker is marked `possible_duplicate_billing`, counted at its reserved cost, and reported as an event. Usage records carry the attempt. Budget failures emit `budget.exceeded`. Costs stay labelled as estimates. Tests: runtime unit tests with the memory store, plus Postgres integration for the lock and for the orphan path.
6. **Operational readiness** (10, 11, 14). Add `/livez` and `/readyz` (database, Temporal, listener, KMS self-test, draining state). Add a Prometheus `/metrics`, protected by a bearer token. Shutdown becomes: withdraw readiness, wait a drain period, end SSE streams, close, with a forced-exit deadline. Write the deployment runbook, backup and recovery, incident response, safe migrations and an updated architecture doc.
7. **Tests and report.** Run every existing suite again, plus the new ones, then write the completion report with an explicit unverified list.

## What will not be claimed

* Real AWS KMS, Temporal Cloud and mTLS against a production cluster will be tested only against local emulators or local TLS endpoints. They are reported as unverified against the real services.
* Cost figures remain catalog estimates. Providers do not return a billed amount per call, so "possible duplicate billing" means a call that may have been charged, not one confirmed by the provider.
* Nothing is deployed.
